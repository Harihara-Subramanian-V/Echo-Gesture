## 3. Human Oversight & Algorithmic Verification

Every line of AI-generated code and every architectural proposal underwent rigorous human and algorithmic verification prior to integration into the master production branch:

1. **Mathematical & Bitwise Parity Auditing:**
   - The Android Kotlin implementations (`KinematicFeatureExtractor.kt`, `TemporalFeatureStandardizer.kt`, and `PredictionDecoder.kt`) were benchmarked against the Python NumPy reference implementations across 100,000+ synthetic and real landmark tensors.
   - Zero bitwise drift ($\Delta = 0.0$) was verified across all 263 feature dimensions prior to hardware deployment.
2. **Physical Hardware Validation (vivo V2416):**
   - AI cannot simulate physical hardware reality. All edge performance figures, frame rates, and latency breakdowns were empirically captured on a physical **vivo V2416 (Qualcomm Snapdragon arm64-v8a, Android 16, API Level 36, Device Serial `10BF3B13J4004R5`)**.
   - 18 end-to-end hardware scenarios were executed, including camera permission revivals, rear-to-front camera flipping, rapid signer movements, and continuous memory leak profiling over 100+ seconds.
3. **Safety & Concurrency Enforcement:**
   - Thread safety contracts (e.g., executing inference on a single-threaded background executor, posting to Android UI via StateFlow, and strictly isolating Android TTS callbacks) were manually designed and verified to ensure zero Main thread blocking and zero ANR (Application Not Responding) events.

## 4. Machine Learning Model Training Provenance

To maintain absolute academic and scientific integrity, **no neural network weights, feature parameters, or quantization scale factors were synthetically hallucinated or generated by AI**:

- **Model Weights & Architecture:**
  - The deployed model (`echogesture_exp_d_int8.tflite`, 135,464 bytes) is a 2-layer Bidirectional GRU network with a dense projection head, trained from scratch using TensorFlow/Keras on extracted MediaPipe landmark sequences.
- **Empirical Dataset Grounding:**
  - The model was trained and evaluated strictly on landmark sequences extracted from the **MS-ASL** dataset across 40 curated lexical classes.
  - WLASL dataset metadata was used exclusively during Phase 1 for lexical vocabulary frequency analysis.
  - **How2Sign was NOT used** in model training or validation.
- **Post-Training INT8 Quantization:**
  - INT8 quantization was performed using representative calibration data drawn from real MS-ASL training partition sequences. The input quantization parameters (`scale = 0.05794047564`, `zero_point = 23`) and output parameters (`scale = 0.00390625`, `zero_point = -128`) are the mathematical result of TensorFlow Lite's post-training integer quantization pipeline.

## 5. Ethical AI, Privacy & Edge Guarantees

EchoGesture was architected with privacy as a foundational principle:

- **100% On-Device Processing:** Zero camera frames, video clips, extracted coordinate arrays, or prediction logs are transmitted across the network or stored in external cloud storage.
- **Offline Speech Synthesis:** The speech feedback system utilizes Android's local TextToSpeech engine (`com.google.android.tts` with `Locale.US`), functioning seamlessly with airplane mode enabled and without data connectivity.
- **Empirical Transparency:** All benchmark statistics, accuracy metrics, and latency numbers reported in `README.md`, `results.csv`, and throughout `reports/` are backed by reproducible execution logs.
